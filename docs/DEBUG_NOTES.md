## 1. adb 命令把 PowerShell 卡死 5 分钟

**现象**：脚本里写 `& adb devices 2>$null | Out-String`，命令不返回，5 分钟不动。

**直接原因**：`adb devices` 会拉起一个**常驻** adb server 进程，它**继承了父进程的 stdout 管道句柄**。
父进程（PowerShell）在等 EOF，但管道还握着在这个常驻进程手里，所以永远等不到。

**根因**：用"管道抓输出"的方式去调用一个会**派生守护进程**的客户端，句柄所有权被继承走了。
这不是 adb 的 bug，是我调用方式错了。

**修法**：改成 `Start-Process -RedirectStandardOutput <临时文件>` + `WaitForExit(20000)`，读取文件。
用超时保证"卡住也不会无限等"。

**验证**：脚本从"卡 5 分钟"变成 **2.2 秒**返回，退出码 3（未连接设备），符合预期。
另外单独跑了一次裸 `adb devices` 掐表：2.5 秒返回、输出 `List of devices attached` 空列表。

## 2. PowerShell 5.1 读 UTF-8 无 BOM 的 .ps1 → 语法错误

**现象**：脚本报
`Missing closing '}' in statement block`，报错里显示的中文是 `鏈?` 这种乱码。

**直接原因**：Windows PowerShell 5.1 默认按 **ANSI/GBK** 解析没有 BOM 的 `.ps1`。
中文被按 GBK 解码成乱码后，引号/花括号的配对就崩了。

**根因**：文件编码与解释器默认编码不匹配，而**错误信息本身也被解码错了**，
所以第一次看到报错时根本不知道是编码问题。

**修法**：把文件重写为 **UTF-8 with BOM**（`UTF8Encoding(true)`），并保留一条注释说明原因。

**验证**：先检查前 3 字节是否为 `239,187,191`，再实跑脚本确认中文正常显示、无语法错误。

## 3. `git commit -m` 里写多行中文 → 提交失败（同一个错误犯了两次）

**现象**：`git commit` 报
`... 'xxx' did not match any file(s) known to git`，提交没产生。

**直接原因**：在 PowerShell 里把多行 + 括号的中文提交信息内联写在 `-m "..."` 中，
命令行被截断，后半段被 git 当成"文件路径"。

**根因**：**同类错第二次**——第一次在另一个项目里也这么干过。
按"同类错犯两次说明缺机制"，光"下次注意"没有用。

**修法**：固定流程——**提交信息一律写到文件，用 `git commit -F <file>`**。
不再使用内联 `-m`。

**验证**：本次提交 `90ac27d`、`50a5367`、`30de46b`、`15419aa` 全部通过 `-F` 完成，一次成功。

## 4. 前端换不了后端地址（`VITE_API_BASE` 是构建期烘焙的）

**现象**：README 教"设 `VITE_API_BASE` 再 `npm run dev`"，但用 `npm run preview`
打开时，页面顶部显示的永远是 `http://localhost:8080`，改成指向别的后端**改不动**。

**直接原因**：`import.meta.env.*` 在 `vite build` 时被**替换成字面量**写进产物，
运行时设环境变量不会生效。

**根因**：把"构建期配置"当成了"运行期配置"。这类错不会报错，只会让人以为改成功了。

**修法**：三级回退——`?api=` URL 参数（`index.html` 先写入全局变量）→ `VITE_API_BASE`
→ 默认地址。这样**同一份构建产物**可以随时换后端。

**验证**：headless Chrome 实拍三张：
`?api=http://127.0.0.1:8080` 顶部显示该地址并拉到 3 条数据；
`?api=/` 与 `?api=javascript:alert(1)` 都被拒绝并回退，页面仍正常。

## 5. 地址参数无效时**静默回退**（最危险的一类）

**现象**：`?api=http://host:8080/api`（带路径）被拒绝后，页面**悄悄**用默认地址，
看起来一切正常——但连的不是使用者的后端。

**根因**：把"降级"实现成了"静默降级"。降级本身是对的，**不说出来**才是问题。

**修法**：`index.html` 在拒绝参数时写入 `window.__INSPECTION_API_WARNING__`，
`App` 读到就渲染黄色警告条，并明写"上面显示的就是实际在用的地址"。

**验证**：实拍确认警告条出现、文案写明"不能带路径（收到 …/api）"、页头仍是 `localhost:8080`。

## 6. 后端落盘只做 `rename` 不 `fsync`

**现象**：代码看起来没问题（`os.WriteFile(tmp)` + `os.Rename`），但断电场景下
可能出现"目标文件存在、内容为 0 或半截"。

**直接原因**：`rename` 只保证**目录项切换**原子，不保证 tmp 的**内容**已经落盘。

**根因**：把"原子替换"误当成"持久化"。数据文件是唯一存储，这个差别是"丢整个库"。

**修法**：写 tmp → `f.Sync()` → `Close` → `rename` → 尽力同步父目录项
（Windows 不支持目录 fsync，所以那里是尽力而为，并写进 README 已知问题）。

**验证**：`TestPersistenceAcrossRestart` 重新 `NewStore` 同一路径断言数据还在；
另外手测"把数据文件清空后启动"，进程拒绝启动并打印原因（而不是静默重建空库）。
