# 演示视频脚本（两段，各 3–5 分钟）

题目第 7 节要求两段视频，至少覆盖：移动观察 → 点击放置 → 填写提交 → React 看到该问题 → React 改状态 → Go 重启后数据仍在。

> 本文件是**录制脚本**（第几秒说什么、点哪里、看什么），不是文案。
> 录之前先跑一遍，确认没有卡顿再正式录。

---

## 录制前的准备（5 分钟）

| 步骤 | 动作 | 为什么 |
|---|---|---|
| 1 | 启动后端：`cd backend; go run . -addr :8080 -data data/issues.json` | 先起后端，Unity 与网页都连它 |
| 2 | 启动前端：`cd web; npm run dev` | → http://localhost:5173 |
| 3 | 打开 Unity 工程，按 Play | 场景是代码生成的，Play 后才有东西 |
| 4 | **先试录 30 秒**，看 Unity 窗口与网页窗口能否同屏 | 避免正式录制时来回切窗口 |
| 5 | 清一次数据：删掉 `backend/data/issues.json` 再重启后端 | 让"空列表 → 新增一条"的过程完整可见 |

推荐布局：左右分屏（左 Unity，右浏览器），或录制时用窗口切换但**每段只切一次**。

---

## 第一段：Unity 客户端（约 3 分钟）

| 时间 | 画面 | 说什么（口语即可，不要念稿） |
|---|---|---|
| 0:00–0:20 | Unity 编辑器，点击 **Play** | "这是 Unity 端。场景不是手工摆的，是运行时用代码生成的——地面、四面墙、三个机柜、设备台、两根管线，都带 Collider，所以射线能命中。" |
| 0:20–0:45 | 用 WASD 走到机柜前，按住右键转视角 | "WASD 移动，按住右键转视角。巡检人员就是这样在现场走动观察的。" |
| 0:45–1:15 | **左键点机柜**，橙色标记出现，右侧表单弹出 | "点击时是从相机发一条射线，和场景求交；标记放在**射线实际命中点**，不是固定高度，也不是投影到某个平面上。" |
| 1:15–1:35 | 连续点三下不同位置 | "再点一次会**替换**上一个标记，不会叠加——保证任何时候最多只有一个待提交标记。" |
| 1:35–2:00 | 点一下右侧表单的输入框 | "点 UI 的时候不会在场景里乱放标记。这里用的是 EventSystem 判断鼠标是否在 UI 上，不是自己算矩形。" |
| 2:00–2:30 | 填标题（**先不填试一次提交**，展示"标题不能为空"），再填好描述、点优先级切换 low→medium→high | "标题必填，前端先挡一次，后端也会再挡一次。优先级点一下换一档。" |
| 2:30–3:00 | 点提交 → 成功提示 → 标记消失；再演示一次**取消**（ESC 或取消按钮），标记被移除 | "提交成功后标记消失，因为已经落库了。取消的话，未保存的标记会被移除，不会留垃圾。" |
| 3:00–3:15 | **停掉后端**，再点一次提交 → 显示失败原因 | "后端不可用时不是静默失败，会明确告诉你连不上哪个地址。" |

## 第二段：管理端 + 持久化（约 3 分钟）

| 时间 | 画面 | 说什么 |
|---|---|---|
| 0:00–0:20 | 浏览器 http://localhost:5173，点"刷新" | "这是管理端，同一个后端、同一份数据。" |
| 0:20–0:50 | 指列表里的这一条（就是刚才 Unity 提交的），念出标题/优先级/位置坐标 | "标题、优先级、状态、位置坐标都在。位置就是刚才射线命中的那个点。" |
| 0:50–1:20 | 把状态从 open 改成 in_progress，再改成 resolved | "状态三档：待处理、处理中、已解决。改完立刻可见。" |

| 2:30–3:00 | 打开 `backend/data/issues.json` 展示内容 | "数据就是这个 JSON 文件，字段和题目第 4 节逐字一致。" |
| 3:00–3:30 | 收尾一句话 | "三端闭环：Unity 上报 → Go 落盘 → React 查看和改状态。已知问题都写在 README 里了。" |

## 录制的三个要点

| 要点 | 原因 |
|---|---|
| **先讲"为什么这样做"，再讲"做了什么"** | 题目第 9 节看的是"是否正确使用射线检测"，不是"你点了鼠标" |
| 失败演示不要剪掉 | 「后端不可用」「标题为空」这两段是评分点（3.1.6 / 3.2.4） |
| 每段控制在 3–5 分钟 | 太长评审不会看完；关键动作都在前 90 秒内最好 |

## 需要准备的两个"坏情况"素材

1. 后端停掉后 Unity 提交 → 失败提示（第一段 3:00）
2. 后端停掉后 React 刷新 → 错误条（第二段 1:20）

这两个是题目明确要求的**失败处理**，比任何漂亮界面都有说服力。
